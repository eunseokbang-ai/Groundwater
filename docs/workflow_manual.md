# 드론 기반 절리군 분석 작업 설명서

- **과제**: 폐석산 복구지 침출수 확산 방지·정밀 차수 기술 현장실증 — WBS 2-1 UAV 기반 불연속 절리대 분포·특성 파악
- **대상**: 드론 취득 → 상용 프로그램(Pix4D/Metashape) → 절리 분석 프로그램(본 저장소) → 차수시설(타겟 그라우팅) 설계 입력자료
- **작성**: 2026-10 · 프로그램 버전 Phase 1 (RGB 사진측량 기반)

이 문서는 사용자(연구자)와 Claude가 함께 작업할 때 **각 단계에서 누가 무엇을 준비하고, 무엇을 넘기고, 무엇을 확인하는지**를 정리한 것이다. 새 작업을 시작할 때 Claude에게 "docs/workflow_manual.md 읽고 시작하자"라고 하면 같은 기준으로 이어서 진행할 수 있다.

```
[1] 드론 취득        RGB(근접 사면 촬영) · LiDAR · 열화상 · GCP/RTK · 현장 절리 실측

        ▼
[2] 상용 프로그램    Pix4D / Metashape → 컬러 점군(LAS/LAZ, EPSG:5186) · 메시 · 품질 보고서

        ▼
[3] 분석 준비        현장 설정 파일(configs/<현장>.yaml) · 벽면 기준선 · 실측 CSV
```

## 1. 드론 데이터 취득

### 1.1 취득 항목과 목적

| 항목 | 목적 | 권장 사양 / 방법 | 프로그램 사용 |
|---|---|---|---|
| **RGB 사진측량** | 절리면 방향·간격·연장성 추출의 기본 자료 | 사면과 평행한 근접(입면) 비행, 사면 지상해상도(GSD) **≤ 1–1.5 cm**, 종중복 80% · 횡중복 70% 이상, 연직·경사 촬영 병행 | **사용 (Phase 1)** |
| **LiDAR** | 낙석방지망·식생 뒤 암반 형상, 그림자 영역 보완 | 다중반사(multi-return) 기록, 사면 근접 비행, 컬러화 | 개발 예정 (Phase 2) |
| **열화상** | 지하수·침출수 유출부(온도 이상) 탐지 | 방사 측정(R-JPEG) 저장, **일출 전 새벽** 또는 강우 2–3일 후, 방사율·기온·습도 기록 | 개발 예정 (Phase 2) |
| **GCP / RTK** | 점군 좌표 정확도, 센서 간 정합 | RTK 드론 + GCP 5점 이상(사면 상·하단 포함), 검사점 별도 | 좌표 기준 |
| **현장 절리 실측** | 자동 추출 결과 검증·보정 | 스캔라인/클리노미터, 노출 사면에서 절리군별 10개 이상 | 사용 (검증) |
| **현장 기록** | 해석 근거 | 낙석방지망·식생 구간, 붕락 흔적, 습윤·용출 지점 사진·위치 | 해석 |
| 강우·촬영 조건 | 열화상·용출 해석 | 선행 강우량, 촬영 시각, 일사 | 해석 |

### 1.2 취득 시 주의

- **연직 정사영상만으로는 부족하다.** 거의 수직인 사면은 정사영상에서 얇은 띠로 압축된다. 프로그램은 점군에서 입면 영상을 직접 만든다. 반드시 **사면을 마주 보는 근접 촬영**을 포함한다.
- **해상도 기준**: 점 간격이 찾고자 하는 최소 절리 간격의 **1/3–1/5 이하**여야 한다. 예를 들어 간격 20 cm 절리를 보려면 점 간격 4–7 cm 이하가 필요하다. 권장 점 간격은 2 cm 내외이다.
- **낙석방지망·식생**: 망 구간은 LiDAR 다중반사로 보완한다. 사진측량만 있을 경우 해당 구간은 "자료 부족"으로 따로 표시한다.
- **좌표계**: 모든 자료를 **EPSG:5186 (GRS80 중부원점)** 으로 통일한다. 정사영상 뷰어, 시추·ERT 위치와도 같은 좌표계를 쓴다.

### 1.3 현장 절리 실측 CSV 형식

`data/raw/<현장>/field/scanline_joints.csv`

```csv
id,dip,dip_direction,x,y,z
J01,72,135,203412.3,384950.1,48.2
J02,15,210,,,
```

- `dip`(경사), `dip_direction`(경사방향)은 필수이다. 단위는 도(°)이고 경사방향은 진북 기준이다.
- `x,y,z`(EPSG:5186)는 선택 항목이다. 있으면 위치별 비교에 쓸 수 있다.
- 자기 편각 보정 여부를 메모로 남긴다.

## 2. 상용 프로그램 처리 (Pix4D / Metashape)

### 2.1 처리 순서

1. 사진 정렬(GCP 입력, 검사점 분리)
2. 고밀도 점군 생성 — 품질 High 이상, 깊이 필터 Mild(절리 모서리 보존)
3. (선택) 메시·텍스처 생성
4. **내보내기**
    - 점군: **LAS/LAZ, RGB 색 포함, EPSG:5186**, 분석 사면 주변으로 자르기
    - 메시(선택): OBJ + 텍스처
    - 품질 보고서(PDF): GCP/검사점 오차, GSD, 점 밀도

### 2.2 품질 확인 (Claude에게 보고서를 주면 함께 검토)

| 항목 | 기준(권장) | 미달 시 |
|---|---|---|
| GCP·검사점 RMSE | 수평·수직 ≤ 3 cm | GCP 재측정·재정렬 |
| 사면 점 간격 | ≤ 2–3 cm | 근접 재촬영 |
| 구멍(누락 영역) | 망·식생 외 큰 구멍 없음 | 촬영 각도 추가 |
| 색 | 노출 균일, 그늘 과도하지 않음 | 흐린 날 재촬영 고려 |

### 2.3 폴더 규칙

```
data/raw/<현장>/
  rgb_photogrammetry/pointcloud.las     ← 컬러 점군 (필수)
  rgb_photogrammetry/model.obj          ← 메시 (선택)
  rgb_photogrammetry/report.pdf         ← 품질 보고서
  lidar/ · thermal/                     ← Phase 2
  field/scanline_joints.csv             ← 실측 절리
data/processed/<현장>/                  ← 프로그램 출력 (자동 생성)
```

`data/`는 용량 때문에 git에 올리지 않는다. 원자료는 별도로 백업한다.

## 3. 분석 준비 — 현장 설정 파일

### 3.1 설정 파일 만들기

`configs/example_site.yaml`을 복사해 `configs/<현장>.yaml`을 만들고 아래를 채운다. Claude에게 "점군 경로 이거고 사면 A 분석할 설정 만들어줘"라고 하면 초안을 만들어 준다.

| 항목 | 내용 | 정하는 방법 |
|---|---|---|
| `paths.point_cloud` | 컬러 점군 경로 | 2단계 출력 |
| `paths.field_measurements` | 실측 CSV | 1.3 |
| `paths.output_dir` | 결과 폴더 | `data/processed/<현장>` |
| `crs` | `EPSG:5186` | 고정 |
| `preprocessing.crop_bbox` | 분석 사면만 남기는 상자 `[xmin,ymin,zmin,xmax,ymax,zmax]` | 점군 뷰어 또는 정사영상 뷰어에서 좌표 확인 |
| `wall_frame.polyline` | 사면을 따라가는 평면 기준선 `[[x,y],...]` | QGIS에서 사면 상단(또는 하단)을 따라 디지타이즈. **굴착지 안에서 사면을 바라볼 때 왼쪽 → 오른쪽 순서** |
| `wall_frame.viewer_point` | 굴착지 안쪽 한 점 `[x,y]` | 굴착지 중앙. 사면의 "앞쪽"을 정한다 |

벽면 좌표계: **u = 측점(기준선을 따라간 거리, m)**, **v = 표고(m)**, **w = 굴착지 쪽 이격(m)**. 모든 결과의 위치는 "측점 ○○ m, 표고 ○○ m"로 보고된다. 기준선이 꺾이는 점은 두 구간이 허용하는 만큼 큰 원호(반지름 ≤ 100 m)로 둥글게 처리한다 — 꺾인 점을 그대로 쓰면 기준선 뒤 몇 m에 있는 암면이 꺾인 점 하나의 측점으로 몰려 입면 영상이 잘린 것처럼 보인다.

### 3.2 점 간격에 맞춘 초기 파라미터

| 파라미터 | 의미 | 초기값 기준 (점 간격 s) |
|---|---|---|
| `preprocessing.voxel_size` | 분석용 다운샘플 크기 | ≈ s (예: 0.02 m) |
| `normals.search_radius` | 법선·평면성 계산 반경 | ≈ 5 s (0.1 m) |
| `patches.link_distance` | 같은 절리면으로 묶는 거리 | ≥ 2 s (0.05 m) |
| `facade.resolution` | 입면 영상 화소 | ≈ 1.2 s 이상 |
| `orientation_sets.max_surface_variation` | 평면성 필터(망·식생·모서리 제거) | 0.1 (거친 절리면이 빠지면 올림) |
| `orientation_sets.min_peak_contrast` | 절리군으로 인정할 밀도 대비 | 3.0 (가짜 군이 많으면 올림) |
| `orientation_sets.min_separation_deg` | 별개 군으로 볼 최소 각도 | 20° |
| `orientation_sets.cone_angle_deg` | 군 평균에서 이 각도 밖은 미분류 | 25° |
| `trace_matching.tolerance`, `max_angle_deg` | 입면 트레이스 확인 기준 | 0.1 m, 20° |
| `patches.min_patch_area` | 절리면으로 인정할 최소 면적 (자체 평면 기준) | 0.2 m² (약 45 cm 사각형; 거친 암반면이 잘게 쪼개진 조각 제외) |
| `vegetation.enabled`, `exg_threshold` | 색 기준 식생 제외 (초록 우세 + ExG > 기준) | 켬, 0.06 (암반이 초록빛이면 올림) |

절리군 간격은 **가상 측선(scanline)** 으로 구한다: 절리군 법선 방향 측선을 절리면 위 여러 지점에 세우고, 측선이 실제로 관통하는 절리면 사이 거리만 간격으로 센다. 벽을 따라 옆으로 떨어져 있어 겹치지 않는 절리면끼리는 간격을 만들지 않는다.

## 4. 프로그램 실행

**보통은 `불연속면_분석_프로그램.bat`을 더블클릭**하고, 왼쪽에서 현장 자료 폴더를 골라 "분석 실행"을 누른다.
설정 파일(YAML)을 직접 쓸 필요는 없다.

현장 자료 폴더 구성 (하위 폴더 포함, 파일 이름은 자유):

| 자료 | 인식 방법 |
|---|---|
| 사진측량 점군 | `.las` `.laz` `.ply` `.pcd` (여러 개면 가장 큰 파일이 기본, 목록에서 변경) |
| 메쉬 | `.obj` (점군이 없을 때만 사용) |
| 라이다 점군 | 경로에 `lidar`·`라이다` 포함 — 2단계(융합)용, 현재는 목록에만 표시 |
| 열화상 | 경로에 `thermal`·`열화상`·`h20t` 포함한 `.tif` — 2단계용 |
| 현장 절리 실측 | `dip`, `dip_direction` 열이 있는 `.csv` (검증용) |
| 벽면 기준선 (선택) | `wall_line.csv`: 열 `kind,x,y` — `wall` 행을 피트에서 벽을 바라본 왼쪽→오른쪽 순서로, `pit` 행 하나는 피트 안쪽 아무 점. 없으면 벽을 직선 하나로 맞춤 (굽은 벽은 넣는 것이 좋음) |

**벽면 기준선은 클릭으로 만든다**: 왼쪽 "벽면 기준선 그리기"에서 정사영상(GeoTIFF 또는 들어 있는 폴더)을 열고, 암사면 하단을 따라 클릭 → 피트 쪽 한 번 클릭(생략하면 DTM 낮은 쪽 자동) → 저장. 같은 폴더 근처에 DTM이 있으면 경사도(30° 이상 급경사)가 겹쳐 보여 암사면을 찾기 쉽다. 정사영상 변천 뷰어에서 타일로 만든 영상은 바로 열리고, 처음 여는 큰 영상은 한 번 타일을 만든다 (data/cache/).
명령줄: `.venv\Scripts\python.exe -m groundwater.viz.wall_digitizer --ortho <정사영상> --out <현장 폴더>`

복셀 크기·법선 반경·패치 연결 거리·입면 영상 해상도는 점군의 점 간격에서 자동으로 정한다 (고급 설정에서 끌 수 있음).
결과는 `<현장 폴더>\분석결과\`에 저장되고, 이번 실행의 설정 전체가 `analysis_config.yaml`로 함께 남는다.
세부 값을 바꿔 다시 돌리려면 이 파일을 고쳐 "설정 파일 (YAML)" 방식으로 불러온다.

명령줄로 실행할 때 (저장소 폴더 `C:\Groundwater`에서):

```bash
.venv\Scripts\python.exe -m groundwater.pipeline --folder <현장 자료 폴더>
```

설정 파일로 실행할 때는 `--folder` 대신 `--config <설정 파일>.yaml`.

대시보드로 보기:

```bash
.venv\Scripts\python.exe -m streamlit run src/groundwater/viz/dashboard/app.py
```

Claude에게 "<현장 폴더>로 불연속면 분석 돌려줘"라고 해도 실행하고 결과를 요약해 준다.

### 4.1 처리 단계 (발표 슬라이드 8쪽과 동일)

| # | 단계 | 내용 | 상태 |
|---|---|---|---|
| 1 | 입력·전처리 | 분석 범위(측점·표고·입면 다각형), 색 기준 식생 제외, 다운샘플 | 구현 |
| 2 | 법선·평면성 계산 | 평면이 아닌 점(식생·망·모서리) 제외 | 구현 |
| 3 | 절리군 탐지 | 스테레오넷 극점 밀도 피크(축 대칭 통계) | 구현 |

## 5. 결과 검토와 조정 (QC)

### 5.1 확인 순서

1. **스테레오넷**: 절리군 수와 방향이 현장 관찰과 맞는가? 굴착면(인공 절개면)이 하나의 "군"으로 잡혔다면 표시해 둔다. 해석에서 제외해야 한다.
2. **실측 비교**: `field_comparison_summary.json`의 RMSE를 본다. **10° 이내면 양호**, 15° 이상이면 조정이 필요하다.
3. **입면 지도**: 절리면 위치가 사진에 보이는 절리와 맞는가? 트레이스 확인율과, 망·식생 구간에 가짜 절리가 몰렸는지 본다.
4. **미분류 비율**: 평면 점 중 군에 배정되지 않은 비율이 너무 크면 `cone_angle_deg`나 `min_peak_contrast`를 조정한다.

### 5.2 증상별 조정표

| 증상 | 조정 |
|---|---|
| 현장에서 보이는 군이 안 잡힘 | `min_peak_contrast` ↓, `min_set_fraction` ↓, 거친 면이면 `max_surface_variation` ↑ |
| 가짜 군이 많음 | `min_peak_contrast` ↑, `bandwidth_deg` ↑ |
| 두 군이 하나로 합쳐짐 | `min_separation_deg` ↓, `bandwidth_deg` ↓ |
| 한 절리면이 여러 조각 | `patches.link_distance` ↑ |
| 평행 절리들이 하나로 합쳐짐 | `patches.link_distance` ↓ (점 간격 2배 아래로는 내리지 않음) |
| 입면 영상에 줄무늬 | `facade.resolution` ↑ |
| 트레이스 잡음 과다 | `trace_mapping.blur_sigma_px` ↑, `hough_min_line_length_px` ↑ |
| 실측 오차 큼 | 실측 위치와 분석 범위가 같은지 먼저 확인 → `crop_bbox` 조정 |

조정은 Claude에게 "Set 2가 실측보다 12° 틀어져 있어, 조정해 봐"처럼 증상으로 말하면 된다. 바꾼 파라미터와 결과 변화를 표로 남겨 준다.

### 5.3 사람이 판단할 것

자동 결과는 **후보**이다. 다음은 반드시 지질기술자가 확인한다.

- 절리군의 지질학적 의미(층리, 엽리, 절리, 단층 구분)
- 굴착·발파로 생긴 인공 파단면 제외
- 망·식생·붕락 구간 결과의 신뢰도

## 6. 해석 — 차수시설 설계 입력자료 만들기

목표는 **"어떤 절리가, 어디서, 얼마나 깊이까지 침출수 통로가 될 수 있는가"** 를 T2(2-4 타겟 그라우팅 설계)가 쓸 수 있는 형태로 넘기는 것이다.

### 6.1 드론이 주는 것과 다른 조사가 줘야 하는 것

| 설계 필요 정보 | 드론(본 프로그램) | 보완 자료 |
|---|---|---|
| 절리군 방향 | ○ (군 평균·분산) | 시추공 영상(BHTV)으로 심부 확인 |
| 절리 간격 | ○ (사면 노출부) | 시추 코어 RQD |
| 연장성·연결성 | ○ (사면 노출 길이, 트레이스) | ERT 저비저항대 연속성 |
| 개구폭·투수성 | × | 수압시험(Lugeon), 시추공 탐사 |
| 심부 연장 | 외삽만 가능 | 시추, ERT 플룸(예비 ERT: 절리대 따라 35 m) |
| 실제 유출 여부 | 열화상·습윤 흔적 (Phase 2) | 수위·수질, 추적자 시험 |

### 6.2 유출 후보 절리 선정 기준

`discontinuity_patches.csv`에서 아래 조건을 점수화해 후보 목록을 만든다. 조건을 정해 주면 Claude가 계산한다.

1. **방향**: 매립지에서 하류·측방(남·동남·서남)으로 기울거나, 차수벽 하부·측단을 지나는 방향
2. **연장성**: `persistence_length_m`가 큰 것 (예: 상위 20% 또는 5 m 이상)
3. **간격·밀집**: 같은 군 절리가 촘촘한 구간(파쇄대 후보)
4. **교차**: 두 군 이상이 교차하는 구간(연결성↑) — 개발 예정, 현재는 수작업 분석
5. **증거**: 트레이스 확인(`trace_confirmed_2d`), 습윤·용출 흔적, 열이상(Phase 2), ERT 저비저항대와의 위치 일치

### 6.3 차수선과의 관계 계산 (현재는 Claude가 스크립트로 수행, 개발 예정 기능)

- **심부 외삽**: 후보 절리면(중심점 + 법선)을 평면으로 연장해 **차수선(연직차수벽·그라우팅 커튼)과 만나는 선과 심도**를 구한다. 그 심도까지 그라우팅이 닿아야 한다.
- **우회 경로**: 차수벽 양 끝 바깥으로 이어지는 절리면을 따로 표시한다(측방 우회 후보).
- **그라우팅공 방향 권고**: 주요 절리군과 가장 큰 각도로 만나는 시추 방향을 찾는다. 군별 가중치(연장성·간격)를 두고 `Σ wᵢ·|nᵢ·d|`를 최대로 하는 방향이다.
- **공 간격 참고값**: 주요 군의 평균 간격(`spacing_mean_m`)보다 작게 해야 각 절리를 한 번 이상 가로지른다.

### 6.4 T2에 넘기는 자료 (설계 입력 패키지)

| 자료 | 형식 | 비고 |
|---|---|---|
| 절리군 요약표 | CSV/표 | 방향, Fisher k, 간격, 연장성, 실측 오차 |
| 유출 후보 절리 목록 | CSV + 입면 지도 | 측점·표고·좌표, 선정 근거 점수 |
| 입면 지도 | PNG / GeoTIFF | 후보 절리, 트레이스, 망·식생 구간 표시 |
| 차수선 교차 결과 | 표 + 단면도 | 교차 심도, 우회 후보 |
| 그라우팅공 방향·간격 권고 | 표 + 스테레오넷 | 근거 군과 가중치 명시 |
| 한계·신뢰도 메모 | 문서 | 자료 부족 구간, 외삽 범위 |

최종 설계(공 배치, 주입재, 압력)는 T2 몫이다. 위 자료는 **설계 입력과 근거**이다.

## 7. Claude와 작업하는 방법

### 7.1 시작할 때

- "docs/workflow_manual.md 읽고, `<현장>` 작업 이어서 하자"라고 시작한다.
- 현장별 작업 일지를 `docs/site_logs/<현장>.md`에 남기자고 하면, 매 작업 끝에 사용 데이터·파라미터·결과·결정사항을 정리해 둔다. Claude는 대화가 바뀌면 이전 내용을 기억하지 못하므로, 일지가 연속성을 지켜 준다.

### 7.2 단계별로 이렇게 말하면 된다

| 단계 | 요청 예 |
|---|---|
| 취득 계획 | "다음 주 취득인데 사면 A 근접 비행 계획 점검해줘 (기체: ○○, 사면 높이 ○○ m)" |
| 상용 처리 검토 | "Pix4D 보고서 여기 있어, 품질 괜찮은지 봐줘" |
| 설정 | "점군 경로는 ○○, 벽면 기준선은 이 좌표들이야. 설정 파일 만들어줘" |
| 실행 | "configs/iksan_a.yaml로 돌리고 결과 요약해줘" |
| 조정 | "실측 오차 RMSE가 14°야. Set 1이 문제인 것 같아, 조정해봐" |
| 해석 | "남·동남 방향으로 기울고 연장 5 m 이상인 절리 뽑아서 입면 지도에 표시해줘" |
| 설계 자료 | "후보 절리를 차수벽 선(이 좌표)까지 연장해서 교차 심도 표 만들어줘" |
| 발표·보고 | "이 결과로 발표용 그림 만들어줘" (기존 슬라이드 스타일 유지) |

### 7.3 Claude가 하는 것 / 사용자가 정하는 것

| Claude | 사용자 |
|---|---|
| 설정 파일 작성, 실행, 로그·결과 요약 | 취득 계획 승인, 현장 판단 |
| 파라미터 조정과 전후 비교 | 절리군의 지질학적 해석 |
| 후보 절리 계산, 교차·외삽 계산 | 후보 채택, 우선순위 결정 |
| 그림·표·보고서 초안 | 최종 검토, 외부 전달 |
| 코드 수정·테스트 | 커밋·푸시 요청 (요청할 때만 수행) |

| 문제 | 원인·해결 |
